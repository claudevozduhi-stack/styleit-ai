# CLAUDE.md — StyleIt AI

ИИ-стилист и виртуальная 3D-примерка одежды по параметрам тела (экзаменационный проект «Основы ИИ», команда StyleIt, группа АЖИОЗ 25-24).
Полная архитектура: `docs/architecture.md`. Этот файл соответствует архитектуре версии 4.

## Общие правила работы

- Отвечать и писать комментарии на русском языке. Имена переменных, функций, файлов и коммитов — на английском.
- Перед написанием нового модуля или изменением архитектуры сначала описать план и согласовать его с пользователем.
- Код чистый, с комментариями (docstring у каждой публичной функции, класса и модуля; поясняющие комментарии у неочевидной логики).
- Никаких заглушек: не оставлять `TODO`, `pass`, `NotImplementedError`, фиктивных данных вместо реальных вызовов или «временных» ответов API. Если задачу нельзя сделать полностью, остановиться и сказать об этом.
- Не хардкодить секреты. Все ключи и адреса — через переменные окружения (`.env`, шаблон в `.env.example`).
- Использовать только свободные и легальные источники (см. раздел «Легальность и приватность»). Не добавлять зависимость, модель, шрифт, иконку или данные, не проверив лицензию.
- Каждое изменение сопровождается тестами; перед завершением задачи прогнать линтер, проверку типов и тесты затронутой части.

## Стек

| Слой | Технология |
|---|---|
| Фронтенд | React 19, TypeScript (strict), Vite 6, Tailwind CSS 4, React Router 7, TanStack Query 5 |
| 3D | three.js, @react-three/fiber; манекен и одежда генерируются кодом (BufferGeometry), без внешних 3D-моделей |
| Анализ фото | @mediapipe/tasks-vision (Face Landmarker), только в браузере |
| Бэкенд | Python 3.12, FastAPI, Pydantic v2, SQLAlchemy 2.0, slowapi (лимиты) |
| БД | SQLite: только каталог и размерные сетки, собирается из CSV скриптом |
| ИИ | Google Gemini API (бесплатный тариф), официальный SDK `google-genai` (Python), модель из `GEMINI_MODEL`, structured output (`response_schema` с Pydantic-моделью) |
| Авторизация | нет: аккаунтов и регистрации нет, лимиты по анонимному ID клиента |
| Иконки и шрифты | Lucide (ISC), Inter (SIL OFL) |
| Деплой | фронтенд — Vercel, бэкенд — Render (Docker) |
| Инструменты | Ruff, mypy, pytest, httpx; ESLint, Prettier, Vitest, React Testing Library, Playwright; pip-audit, pip-licenses, license-checker-rseidelsohn |

## Легальность и приватность (обязательно)

### Персональные данные
- Сервер не получает и не хранит персональные данные: нет аккаунтов, e-mail, имён, телефонов, IP в логах.
- Мерки, цветотип и образы хранятся только в localStorage браузера. На сервер мерки передаются в теле запроса для расчёта и нигде не сохраняются и не логируются.
- Фото пользователя никогда не отправляется на сервер и в Gemini API. Обработка только в браузере через MediaPipe, наружу уходят только HEX-цвета. Фото не сохраняется даже локально.
- На бесплатном тарифе Gemini Google может использовать запросы для улучшения своих продуктов. Поэтому в Gemini отправляются только обезличенные данные: числа мерок, HEX-цвета, стиль, бюджет, ID и факты товаров. Никаких имён, текстов пользователя, фото, ID клиента.
- Логирование: запрещено писать в логи тело запросов с мерками, заголовок `X-Client-Id` и IP. Статистика ИИ (`services/metrics.py`, `GET /stylist/stats`) хранит в памяти только число запросов, ошибок, повторов, время ответа и токены.
- Любая новая функция, которая требует хранить данные о человеке на сервере, сначала согласуется с пользователем.

### Авторское право и лицензии
- Разрешённые лицензии зависимостей: MIT, BSD, Apache 2.0, ISC, PSF, public domain, CC0. GPL, AGPL и неизвестные — не добавлять.
- 3D: манекен и одежда генерируются нашим кодом. Внешние 3D-модели не добавлять без согласования; логотипы и узнаваемый дизайн брендов — запрещено.
- Каталог: храним только факты (название, бренд, категория, цвет, цена, размерная сетка, ссылка, дата сбора). Фото и тексты описаний магазинов не копировать и не загружать. Не парсить сайты автоматически и не обходить их защиту.
- Каждый новый сторонний ресурс сразу добавлять в `THIRD_PARTY_LICENSES.md` (название, автор, лицензия, ссылка).

### Безопасность
- Секреты только в переменных окружения; `.env` в `.gitignore`.
- CORS только для домена фронтенда; заголовки CSP, HSTS, X-Content-Type-Options, Referrer-Policy.
- Лимит частоты запросов на каждый эндпоинт ИИ.
- Все входные данные валидируются Pydantic-схемами с допустимыми диапазонами.
- Пользовательский текст не вставляется в промпт как инструкция; ответ ИИ принимается только по JSON-схеме и проверяется кодом.

## Правила кода

### Общие
- Одна функция — одна задача; функции до ~40 строк, файлы до ~300 строк.
- Понятные имена без сокращений (`recommended_size`, а не `rs`).
- Ошибки не глотать: логировать и возвращать понятное сообщение пользователю.
- Единицы измерения: длины в сантиметрах, вес в килограммах, цены в тенге (целое число).

### Бэкенд (Python)
- Полная типизация, mypy в strict-режиме. Pydantic-схемы на входе и выходе каждого эндпоинта.
- Слои не смешивать: роутер → сервис → репозиторий. В роутерах нет бизнес-логики и SQL.
- Асинхронный ввод-вывод (`client.aio` из `google-genai` для Gemini); SQLite только на чтение во время работы.
- Ответы Gemini всегда запрашивать через structured output и валидировать через Pydantic. ИИ выбирает товары только по ID из переданного списка кандидатов; ID и бюджет проверяются кодом, при ошибке — повторный запрос с описанием ошибки (не более 2 повторов).
- Промпты хранятся в `app/ai/prompts/` отдельными файлами, не внутри бизнес-логики.
- Стиль: Ruff (форматирование и линтинг), длина строки 100.

### Фронтенд (TypeScript)
- `strict: true`, без `any`. Типы ответов API в `src/types/`.
- Функциональные компоненты и хуки; запросы к API только через TanStack Query.
- Доступ к localStorage только через модуль `src/storage/`, с обработкой ошибок (приватный режим браузера).
- 3D-логика (сечения манекена, смещение одежды на запас, раскраска зон посадки) — в чистых функциях, отдельно от компонентов, чтобы её можно было тестировать.
- Интерфейс адаптивный, проверять на ширине телефона.
- Стиль: ESLint + Prettier.

### Git
- Ветки `feature/<кратко>`, `fix/<кратко>`; в `main` только через pull request.
- Коммиты в формате Conventional Commits: `feat:`, `fix:`, `test:`, `docs:`, `refactor:`.

## Команды

### Локальный запуск
```bash
cd backend && pip install -e ".[dev]"
python -m scripts.import_catalog             # CSV → SQLite (backend/catalog.db)
uvicorn app.main:app --reload                # API на http://localhost:8000 (документация /docs)

cd frontend && npm install
npm run dev                                  # http://localhost:5173
```

### Проверки бэкенда
```bash
cd backend
ruff check . && ruff format --check .        # линтер и форматирование
mypy app scripts                             # проверка типов
pytest                                       # все тесты
pytest tests/unit                            # только unit-тесты
pytest tests/unit/test_size_engine.py -k chest   # один тест по имени
pytest --cov=app --cov-report=term-missing   # покрытие
pip-audit                                    # уязвимости зависимостей
pip-licenses --partial-match --fail-on="GPL;Affero"   # запрещённые лицензии
```

### Проверки фронтенда
```bash
cd frontend
npm run lint                                 # ESLint
npm run typecheck                            # tsc --noEmit
npm run test                                 # Vitest
npm run test -- src/features/avatar          # тесты одной папки
npm run e2e                                  # Playwright, основной сценарий
npm run build                                # production-сборка
npm audit --omit=dev                         # уязвимости зависимостей
npm run licenses                             # запрещённые лицензии
```

## Переменные окружения

`CATALOG_DB_PATH`, `GEMINI_API_KEY`, `GEMINI_MODEL`, `CORS_ORIGINS`, `FREE_CAPSULES_PER_DAY`, `RATE_LIMIT` (бэкенд); `VITE_API_URL` (фронтенд).

## Определение готовности задачи

1. Код без заглушек, с комментариями.
2. Линтер, проверка типов, тесты, аудит уязвимостей и лицензий затронутой части проходят.
3. Новый эндпоинт виден в `/docs` и покрыт интеграционным тестом.
4. Персональные данные не попадают на сервер, в логи и в Gemini API; новые ресурсы внесены в `THIRD_PARTY_LICENSES.md`.
5. Основной сценарий (мерки → капсула → размер → 3D-примерка → смета) не сломан.
