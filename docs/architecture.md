# StyleIt AI — архитектура прототипа (версия 5, согласована)

Основа: КТ2 (StyleIt AI), положение и памятка ОИИ. Код пишем только после согласования этого документа.

Изменения версии 5: основной ИИ-сервис — Claude API (Anthropic, модель `claude-haiku-5-5`, около $0.001 за капсулу), потому что бесплатный тариф Gemini недоступен для аккаунта команды. Gemini остаётся запасным и включается переменной `AI_PROVIDER=gemini`.

Изменения версии 4: ИИ-сервис снова Google Gemini API на бесплатном тарифе (решение команды: без расходов на API).

Изменения версии 3: 3D-аватар и одежда строятся процедурно в коде, без Blender и сторонних 3D-моделей.

Изменения версии 2: добавлены требования легальности и приватности (раздел 2). Из-за них убраны аккаунты и хранение мерок на сервере, анализ фото перенесён в браузер, фото товаров магазинов не копируются, Supabase заменён на SQLite только с каталогом.

## 1. Что требуется по положению (влияет на архитектуру)

- ИИ выполняет основную функцию, а не вспомогательную; есть свои данные или база (критерий «Применение ИИ», 20 баллов).
- Не менее 3 работающих функций, связанных в один сценарий; работает на реальных данных.
- Прототип открывается по ссылке с чужого устройства, есть тестовый доступ, ссылка живёт до конца сессии.
- Исходники ссылкой (GitHub). В документации обязателен раздел «Риски и этика: ошибки ИИ, персональные данные, предвзятость».
- Сроки: КТ3 (основной сценарий работает) — 29 ноября; КТ4 (тест на 5+ пользователях) — 6 декабря; финал — 11 декабря, 23:59.
- Из интервью: 3 из 5 респондентов боятся загружать фото; нужны точный размер, визуализация облегания, бюджет, Freemium.

## 2. Легальность, авторское право и приватность

Принцип: используем только то, что разрешено лицензией, и не собираем персональные данные вообще.

### 2.1. Персональные данные: сервер их не получает
- **Нет регистрации и аккаунтов.** Нет e-mail, имён, паролей, телефонов. Тестовый доступ — просто ссылка.
- **Мерки хранятся только в браузере пользователя** (localStorage) и удаляются кнопкой «Удалить мои данные». На сервер они уходят обезличенными числами только для расчёта конкретного запроса и не записываются ни в БД, ни в логи.
- **Фото не покидает устройство.** Цветотип определяется в браузере: MediaPipe Face Landmarker (Apache 2.0) находит лицо, код берёт усреднённые цвета кожи, волос и глаз. На сервер и в ИИ-сервис уходят только 3 HEX-цвета, без изображения. Фото не сохраняется даже в браузере.
- Перед загрузкой фото — явное согласие и пояснение, что изображение обрабатывается только на устройстве.
- Freemium-лимит считается по случайному анонимному ID, который генерирует браузер. Он не связан с личностью, IP не хранится.
- Сервер хранит только обезличенную статистику ИИ-запросов (тип, время ответа, токены, успех) для раздела «Экономика» и тестирования.
- Так прототип соответствует Закону РК «О персональных данных и их защите»: персональные данные не собираются и не передаются третьим лицам.

### 2.2. ИИ-сервис (Claude API, запасной — Google Gemini API)
- Провайдер выбирается переменной `AI_PROVIDER` (`claude` по умолчанию или `gemini`); стилист работает с общим протоколом `LLMClient` и не зависит от провайдера.
- Claude: официальный SDK `anthropic`, модель из `CLAUDE_MODEL` (по умолчанию `claude-haiku-5-5`, $0.10 / $0.50 за 1 млн токенов ввода и вывода, около $0.001 за капсулу; `claude-sonnet-5-5` — сильнее и дороже). Ответ запрашивается через structured outputs (`output_config.format` с JSON-схемой) и всё равно проверяется Pydantic и кодом.
- Gemini: модель из `GEMINI_MODEL` (`gemini-3.5-flash`). По условиям бесплатного тарифа Google использует запросы для улучшения своих продуктов.
- Для обоих провайдеров отправляются только обезличенные данные: числовые мерки, HEX-цвета, стиль, бюджет и список товаров-кандидатов. Имён, текстов пользователя, фото и ID клиента там нет. Это указываем в разделе «Риски и этика» документации.
- Лимиты бесплатного тарифа действуют на проект и сбрасываются в полночь по тихоокеанскому времени; при превышении API возвращает понятную ошибку, а наш лимит на анонимный ID не даёт одному пользователю израсходовать квоту.
- Ответ запрашивается по JSON-схеме (structured outputs) и дополнительно проверяется кодом.
- Ответы ИИ помечаются в интерфейсе как рекомендации справочного характера.

### 2.3. Каталог магазинов РК
- Фото товаров, описания и дизайн сайтов магазинов защищены авторским правом, поэтому **мы их не копируем и не храним.**
- Храним только факты: название товара, бренд, категория, цвет, цена, размерная сетка в цифрах, ссылка на страницу товара. Факты и цифры не являются объектом авторского права.
- Вместо фото товара показываем собственный 3D-рендер категории в цвете товара и кнопку «Открыть в магазине».
- Сбор каталога вручную, без парсинга и без обхода защиты сайтов. Для каждого магазина фиксируем дату сбора цен. В интерфейсе пометка «цены на дату сбора, актуальные — в магазине».
- Если у магазина есть официальная партнёрская программа или открытая выгрузка (фид), используем её в первую очередь.

### 2.4. 3D-модели, шрифты, иконки, библиотеки
- **Аватар и одежда:** одежда строится нашим кодом на three.js (см. раздел 6). Тело — базовая сетка MakeHuman под лицензией CC0 (public domain), код MakeHuman (AGPL) не используется; источник и коммит указаны в THIRD_PARTY_LICENSES.md. Логотипы и узнаваемый дизайн брендов не воспроизводим.
- **Шрифты:** только Google Fonts под SIL Open Font License (например, Inter) или системные.
- **Иконки:** Lucide (ISC).
- **Библиотеки:** только с разрешительными лицензиями (MIT, BSD, Apache 2.0, ISC). Проверка в CI: `pip-licenses` и `license-checker`, сборка падает при GPL/AGPL/неизвестной лицензии.
- Все сторонние ресурсы и их лицензии перечисляются в `THIRD_PARTY_LICENSES.md` и в разделе 11 документации.
- Сам проект публикуем под MIT.

### 2.5. Защита прототипа
- Только HTTPS (Vercel и Render дают его по умолчанию).
- Ключи Claude и Gemini API только на сервере, в переменных окружения; в репозитории только `.env.example`. Включено сканирование секретов GitHub.
- CORS только для домена фронтенда.
- Валидация всех входных данных Pydantic-схемами, допустимые диапазоны мерок.
- Ограничение частоты запросов (slowapi) на анонимный ID и на IP в памяти, без записи IP.
- Заголовки безопасности: Content-Security-Policy, X-Content-Type-Options, Referrer-Policy, HSTS.
- Защита от prompt injection: пользовательский текст не попадает в промпт как инструкция, ответ ИИ принимается только по JSON-схеме и проверяется кодом.
- Проверка уязвимостей зависимостей: `pip-audit` и `npm audit` в CI, Dependabot.
- Тестирование на пользователях: устное или письменное согласие, в отчёте только обезличенные результаты («Респондент 1, 19 лет»).

## 3. Пользовательский сценарий

1. Пользователь открывает ссылку, регистрации нет.
2. Ввод мерок: пол, рост, вес, обхваты груди, талии, бёдер, ширина плеч, длина ноги (опционально). Хранятся в браузере.
3. Опционально фото: цветотип определяется на устройстве, фото не отправляется.
4. Выбор стиля (casual, деловой, спорт и т. д.), повода и бюджета в тенге.
5. ИИ собирает капсульный гардероб из реального каталога магазинов РК и объясняет, почему вещи подходят под фигуру и цветотип.
6. Для каждой вещи: рекомендуемый размер по сетке бренда и посадка по зонам.
7. 3D-примерочная: аватар по меркам, на него надевается вещь, зоны подсвечиваются (свободно / в самый раз / тесно), можно сравнить соседний размер.
8. Смета образа, ссылки на магазины, замена отдельной вещи, сохранение образов в браузере.

## 5. Модули бэкенда

1. **catalog** — товары: категория, цвет, стиль-теги, цена, ссылка, дата сбора, размерная сетка, 3D-шаблон категории.
2. **body_analysis** — тип фигуры детерминированно по меркам (песочные часы, треугольник, перевёрнутый треугольник, прямоугольник, овал); цветотип по HEX-цветам: правило по тону и контрасту + уточнение ИИ, палитра рекомендуемых цветов.
3. **size_engine** — подбор размера: мерки против сетки бренда с нормой свободы облегания по категории; результат — размер, уверенность и разница по зонам в сантиметрах.
4. **stylist (капсула)** — гибридный подход против галлюцинаций:
   - шаг 1, код: отбор кандидатов (есть размер, цена в бюджете, стиль, палитра);
   - шаг 2, Claude: из кандидатов (только по ID) собирает 3–5 образов и капсулу, объясняет выбор;
   - шаг 3, код: проверка (ID существуют, бюджет не превышен), при ошибке повторный запрос, не более 2 раз.
5. **estimate** — смета: сумма по образам и капсуле, остаток бюджета.
6. **limits** — Freemium: N бесплатных генераций капсулы в день на анонимный ID; подписка показывается как тариф, без реальных платежей.
7. **metrics** — обезличенная статистика ИИ-запросов.

## 6. Фронтенд и 3D-примерочная

- **Анатомическое тело (основной вариант):** базовая сетка MakeHuman (данные CC0, код MakeHuman не используется). Скрипт `tools/build_body_model.py` скачивает данные с закреплённого коммита и собирает компактный файл `public/models/body-v1.bin` (~500 КБ в gzip): вершины тела, части тела по весам скелета, центры суставов, морфы пола, веса и обхватов груди, талии и бёдер, плюс наш морф «манекен», который сглаживает лицо и соски. В браузере (`features/avatar/humanFit.ts`) тело подгоняется под мерки: морф пола и комплекции по индексу массы, руки опускаются из A-позы, тело масштабируется до роста, затем морфы обхватов подбираются итерациями, а остаток добирается плавным масштабом сечений. Обхват меряется «сантиметром» — периметром выпуклой оболочки горизонтального среза. Грудь ищется по самой выступающей точке, талия — по наименьшему обхвату, бёдра — на уровне тазобедренных суставов. Рост и обхваты совпадают с мерками до 1 см (тест).
- **Одежда на теле по скану:** с подогнанного тела снимаются срезы (`humanSections.ts`), у каждого — контур по 48 направлениям. Одежда раздвигает контур наружу на запас из размерной сетки, ниже груди ткань свисает, а не облегает, юбка закрывает ноги выпуклой оболочкой. Пока файл тела грузится или если он недоступен, показывается процедурный манекен ниже.
- **Аватар (процедурный манекен, запасной):** тело описывается набором горизонтальных сечений-эллипсов на заданных высотах (шея, плечи, грудь, талия, бёдра, бедро, колено, щиколотка; руки отдельно). Высоты берутся из роста по антропометрическим пропорциям, а размеры эллипсов подбираются так, чтобы их периметр равнялся обхвату из мерок (формула Рамануджана). Между сечениями поверхность сглаживается сплайном, получается гладкая сетка (BufferGeometry). Манекен стилизованный, без лица, что подходит под идею приватности.
- **Одежда:** строится из той же сетки тела. Для каждой зоны вещь смещается наружу на величину запаса, который даёт размерная сетка товара (обхват вещи минус обхват тела), и обрезается по своей длине и форме категории (футболка, брюки, куртка, затем остальные). Поэтому вещь на экране показывает реальную посадку: большой размер выглядит свободнее, маленький плотнее. Цвет берётся из товара.
- **Тесный размер:** даже самая тесная вещь лежит поверх тела с отступом не меньше 0,5 см, поэтому манекен не просвечивает. Теснота видна по натяжению (`features/fitting/strain.ts`): в тесных зонах складки разглаживаются, ткань светлеет и на ней видны поперечные складки натяжения, сильнее при большей нехватке обхвата. Рядом с выбором размера показывается предупреждение: в какой зоне и на сколько сантиметров размер мал и какой размер взять.
- **Ткани и свет:** у каждой ткани свои свойства материала (`features/fitting/fabric.ts`) и карты-сканы нормалей и шероховатости из Poly Haven (CC0): трикотаж, поплин, деним, шерсть-ёлочка, кожа. Скрипт `tools/build_fabric_textures.py` скачивает их с проверкой MD5 и уменьшает до 512 px (~400 КБ на все ткани); карты грузятся лениво, только для надетых тканей, а пока грузятся — работает процедурный рельеф. Развёртка одежды идёт по длине дуги контура с целым числом повторов по кругу, поэтому рисунок не растягивается и смыкается без шва; повтор равен настоящему размеру куска ткани. Нормали сетки сглаживаются по высоте, чтобы на тёмной гладкой ткани не было горизонтальных полос бликов. Камеру можно приблизить до 0,6 м, чтобы рассмотреть фактуру.
- **Швы и строчка:** кодом, без текстур (`features/fitting/seams.ts`, `surfacePath.ts`). Линии прокладываются прямо по решётке лофта, поэтому ложатся в складки: боковые швы (по бокам туловища и штанин), пройма у рукава, строчка вдоль подола, манжет и горловины на заданном расстоянии от края, у брюк и юбок — пояс со швом и двумя строчками. Строчка — пунктир по длине линии (стежок 3,5 мм через 1,5 мм), нитка в тон ткани; у денима — двойная медная отстрочка, у трикотажа — двойная плоская строчка подола. Все линии одной вещи — одна дополнительная сетка. Ткань берётся по названию товара («кожаная», «джинсовая», «шерсть», «трикотаж»), иначе по категории. Цвета товара переводятся из sRGB в линейное пространство, поэтому тёмные вещи не выглядят блёклыми. Свет студийный и мягкий: размытое окружение-«комната» и основной свет с мягкой тенью.
- **Посадка:** считается численно в size_engine, на вещи зоны окрашиваются (синий — свободно, зелёный — в самый раз, красный — тесно), есть сравнение соседнего размера.
- Это честнее для прототипа, чем «надевание» готовой модели: форма вещи вытекает из реальных цифр размерной сетки, а весь 3D-код наш.
- **Локальные данные:** мерки, цветотип и сохранённые образы — в localStorage, кнопка полного удаления.
- Адаптивный интерфейс, работает на телефоне.
- **Лучшие образы под капсулой:** в браузере код (`features/capsule/outfits.ts`) берёт образы стилиста и сам собирает все допустимые сочетания из вещей капсулы (верх + низ или платье, по желанию верхняя одежда), оценивает их по уверенности размера, сочетаемости цветов, близости к палитре цветотипа и общему стилю и показывает до 6 лучших. Дополнительных запросов к ИИ нет.
- **Весь образ в 3D (`/looks/:id`):** вещи надеваются на манекен слоями (низ или платье, верх, верхняя одежда); верхний слой расширяется до выпуклой оболочки нижнего с зазором (`features/fitting/layers.ts`, `enclose.ts`), поэтому низ длинной куртки над штанинами ровный, а расширение плавно сходит на нет по высоте без ступенек. Размер каждой вещи можно переключить.

## 7. Модель данных (только сервер, без персональных данных)

- `stores` (id, name, url, collected_at)
- `brands` (id, name, store_id)
- `size_charts` (id, brand_id, category, gender, size_label, chest_min/max, waist_min/max, hips_min/max, length)
- `products` (id, store_id, brand_id, title, category, gender, price_kzt, color_name, color_hex, style_tags, season, product_url, garment_template, collected_at)
- Статистика ИИ-запросов хранится не в БД, а в памяти процесса (число запросов, ошибок, повторов, среднее время, токены) и отдаётся `GET /stylist/stats` — без анонимного ID и без содержимого запросов

Каталог (свои данные): 150–300 реальных товаров из 3–5 магазинов РК в CSV, импорт скриптом.

## 8. API

- `GET /catalog` — фильтры: категория, цена, стиль, пол
- `POST /analysis/body` — мерки → тип фигуры
- `POST /analysis/color` — HEX-цвета кожи, волос, глаз → цветотип и палитра
